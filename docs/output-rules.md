# 输出纪律（项目强制约定 · 20 条）

> 适用范围：本项目所有产出——代码、脚本、文档、清单、命令、回复。
> 违反任一条视为交付不合格，PR 不予合并。

## 一、任务完整性

| # | 纪律 | 落地方式 |
|---|---|---|
| 1 | 收到任务一次性完整输出，禁止主动暂停、中途停止、自动分段打断 | 单次交付到门禁可判状态为止；确需等待外部输入时，先做完所有不依赖该输入的项 |
| 2 | 不缺步骤、不少参数、不漏配置、不省关键逻辑 | 每步含：命令/路径/参数/预期输出 |
| 3 | 不自行简化代码、不删注释、不去边界判断、不去异常处理 | 代码给可直接复制的完整版，含 try/except 与参数校验 |
| 4 | 未声明精简时，全部操作分精细化步骤 | 写明点击位置、参数、输入内容 |
| 5 | 代码/脚本过长时完整贴出，不截断、不贴片段 | 超长时分块输出并自动接续 |
| 6 | 报错、依赖、前置环境一次性列出 | 每份 runbook 带「前置条件」与「已知坑」两节 |
| 7 | 不提前结束对话；任务完成后等待指令 | 回复末尾不写"如需…请告知"式收尾 |
| 8 | 所有配置文件给完整成品 | `.gitignore` / `*.json` / `*.ini` 全量，不给片段 |
| 9 | 逆向/内存/工具类内容分四块：【原理】【代码】【使用步骤】【风险备注】 | 四块缺一不可 |
| 10 | 不省略结构体、偏移、常量、枚举 | 相关数据一次性全给，见 `docs/protocol/msgid.csv` 与 `schema/commands.h` |
| 11 | 整理文档/清单/表格时条目齐全，不偷偷少条目、不合并条目 | 559 条命令一条不落，按域分组但不合并 |
| 12 | 不猜需求；有歧义只在末尾统一问一次 | 单次回复最多一次集中提问，位于正文末尾 |
| 13 | 编译部署、环境搭建从 0 写 | 含安装、路径、环境变量、测试验证全流程 |
| 14 | 脚本可直接复制运行 | 需手改的变量用 `TODO:` 显式标记并集中列在脚本头部 |
| 15 | 未标"只给摘要"时一律详细输出 | 不自动压缩 |
| 16 | 内容有上限时主动分块并自动接续 | 分块边界写「续下块」，不需用户重复指令 |
| 17 | UI / Winform / Electron 需求给完整控件、属性、布局 | 不缺控件，含事件绑定 |
| 18 | 方案先写【注意事项】坑点 | 坑点前置，不做事后提醒 |
| 19 | 连续任务记住上下文参数 | 版本、端口、路径、选型以 `config/variables.json` 为唯一真源，每轮引用不重问 |
| 20 | 全程不暂停、不中断、不缺项、不漏步骤、不偷减细节 | 直至用户明确说结束 |

## 二、四块结构的固定顺序（第 9 条展开）

```markdown
【原理】  算法/机制/数据结构为什么长这样，附源码位置（文件:行号）
【代码】  完整可运行实现，含依赖声明与入口
【使用步骤】 逐条命令，含参数、预期输出、失败判据
【风险备注】 会踩的坑、不可逆操作、备份要求、回滚方式
```

## 三、变量真源（第 19 条展开）

所有数字只来自一处，其余位置引用，不重复定义：

| 变量 | 真源文件 | 消费方 |
|---|---|---|
| 客户端版本 / 文件数 / 树指纹 | `config/variables.json` | `docs/client-versions.md`、`docs/intake/ledger.md` |
| 协议 559 条 | `docs/protocol/msgid.csv` | `docs/protocol/protocol.md`、P3 服务端 |
| 端口表 | `docs/architecture.md §3` | `config/server/*.ini`、runbook |
| 任务 DAG 与工时 | `tasks/registry.json` | `state/queue.json`、Issue 任务单 |

改一处必须同步下游，`01 校验` 会拦不一致。

## 四、验收口径

| 交付类型 | 合格判据 |
|---|---|
| 代码 | `python -c "import py_compile,sys;py_compile.compile(...)"` 通过 + 自检用例通过 |
| 脚本 | 本地跑一次退出码 0，输出贴进 PR「验收证据」 |
| 文档 | 条目数与真源一致（如 559 条 = 559 行），差 1 条即不合格 |
| 配置 | 整文件提交，`01 校验` 的 JSON/INI 解析通过 |
